# Текущий алгоритм формирования цены

## Назначение

Документ фиксирует поток получения параметров заказа и формирования цены после вынесения расчёта в общий модуль. Клиент и сервер используют одну чистую функцию, но сервер остаётся источником сохраняемой суммы.

## Загрузка исходных данных на клиенте

При открытии страниц администратора и работника клиент параллельно загружает:

1. `GET /orderParameters` — параметры заказа, доступные текущей компании, их опции и зависимости.
2. `GET /price` — строки прайса текущей компании.

Запросы запускаются в:

- `client/src/pages/orders/OrdersPage.tsx`;
- `client/src/pages/workerOrder/WorkerOrderPage.tsx`.

### Параметры заказа

Thunk `getOrderParametersList` расположен в `client/src/entities/orderParameters/model/slice.ts`. Ответ `GET /orderParameters` имеет вид:

```ts
{
  parameters: Array<{
    id: number;
    name: string;
    translationRu: string;
    type: "SELECT" | "SELECT_LIST" | "INPUT" | "GRAPH_INPUT";
    order: number | null;
    options: Array<{
      id: number;
      translationRu: string;
    }>;
  }>;
  options: {
    parameterOptionDependence: string;
    optionOptionDependence: string;
  };
}
```

Сервер формирует ответ в `server/src/orderParameters/orderParameters.service.ts`:

- определяет компанию по авторизованному пользователю;
- берёт разрешённые ID параметров и опций из `companiesParametersOptions`;
- возвращает только доступные компании параметры и опции;
- передаёт зависимости параметров и опций строками JSON.

На клиенте зависимости разбираются и сохраняются в `state.orderParameters`. Селектор `formatedOrderParametersList` из `client/src/entities/orderParameters/model/selectors.ts` использует их, чтобы:

- скрывать параметры, которые ещё не должны быть доступны;
- ограничивать варианты параметра в зависимости от ранее выбранной опции;
- сортировать параметры по полю `order`.

### Прайс

Thunk `getPriceList` расположен в `client/src/entities/price/model/slice.ts`. `GET /price` возвращает строки прайса компании:

```ts
type PriceItem = {
  value: number;
  conditions: Array<{ id: number }>;
  discountImpact: boolean;
};
```

Сервер формирует список в `server/src/price/price.service.ts`. Для каждой строки передаются цена, признак влияния скидки и ID опций-условий. `companyId`, внутренний ID строки и `mainOptionId` клиенту не возвращаются.

## Получение выбранных значений

Компонент `client/src/features/editOrderForm/ui/SwitchParameterType.tsx` записывает каждое изменение формы через `setOrdersValue` в:

```ts
state.order.ordersValue[orderId][parameterName]
```

Значение зависит от типа параметра:

- `SELECT` — ID выбранной опции в виде строки;
- `SELECT_LIST` — объект `{ [optionId]: count }`;
- `INPUT` и `GRAPH_INPUT` — введённое значение.

Для существующего заказа селектор `selectOrderParametersOrdersValue` восстанавливает такой же объект из `optionValues`, если пользователь ещё не начал редактирование.

Перед расчётом селектор `usefulOrderValuesWithOptions` оставляет только параметры, у которых есть опции. Текстовые и графические значения, `id` и `active` в расчёте цены не участвуют.

## Общий модуль расчёта

Единственная реализация алгоритма находится в локальном пакете:

`packages/pricing/src/calculate-order-price.ts`.

Функция `calculateOrderPrice` не зависит от Redux, React, NestJS или Sequelize. Она получает три источника данных:

1. выбранные значения параметров текущего заказа;
2. загруженный прайс компании;
3. список доступных параметров и опций.

Расчёт выполняется следующим образом:

1. Выбранные значения преобразуются в карту `optionId -> count`. Для одиночной опции количество равно `1`, для `SELECT_LIST` используется введённое количество.
2. Отдельно формируется список ID всех выбранных опций с положительным количеством.
3. В списке параметров ищется параметр с техническим именем `discount`.
4. Процент скидки читается из `translationRu` выбранной опции через `parseInt`; коэффициент равен `1 - процент / 100`.
5. Строка прайса считается подходящей, если все ID из её `conditions` присутствуют среди выбранных опций.
6. При обработке подходящих строк ранее найденная строка удаляется, если все её условия входят в условия новой, более специфичной строки.
7. Стоимость строки равна `value`, умноженному на количества всех опций из `conditions`.
8. Для `totalValueWithDiscount` скидка применяется только к строкам с `discountImpact: true`.
9. Селектор возвращает две суммы:

```ts
{
  totalValue: number;
  totalValueWithDiscount: number;
}
```

Клиентский селектор `orderTotalValue` в `client/src/entities/orderParameters/model/selectrors.total.ts` только передаёт данные из Redux в общую функцию. Компонент `client/src/features/editOrderForm/ui/OrderTotalValue.tsx` показывает сумму со скидкой и, если она отличается, сумму без скидки.

## Серверный контроль суммы

Цена, показанная в форме, не считается окончательным доверенным значением. При создании и редактировании заказа `server/src/orders/orders.service.ts` вызывает:

`server/src/price/price.service.ts -> calculateTotalValue()`.

Сервер заново получает разрешённые параметры и прайс компании, преобразует Sequelize-модели в обычные объекты и вызывает ту же `calculateOrderPrice`. Полученные `totalValue` и `totalValueWithDiscount` записываются в заказ. Клиент не передаёт готовую сумму для сохранения.

Таким образом:

- клиентский расчёт нужен для немедленного отображения цены в форме;
- серверный расчёт является источником суммы, сохраняемой в БД;
- изменение алгоритма выполняется в одном общем модуле и проверяется его regression-тестами.

## Особенности, значимые для корректировки алгоритма

- Скидка зависит от технического имени параметра `discount` и числового текста в `translationRu` его опции.
- Количество умножается для каждой опции, входящей в `conditions`; строка с несколькими количественными условиями умножает их количества между собой.
- Выбор более специфичной строки зависит от порядка строк прайса: текущий `reduce` удаляет менее специфичную уже накопленную строку, но не выполняет симметричную проверку, если менее специфичная строка встретилась позже.
- Клиент и сервер подключают локальную зависимость `@autoservice/pricing`; пакет должен быть собран до запуска приложений. Dockerfile обоих приложений выполняет эту сборку.
- Зависимости видимости параметров влияют на форму, но сам подбор цены основан на фактически сохранённых выбранных опциях.
