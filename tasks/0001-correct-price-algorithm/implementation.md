# Итог реализации

## Поведение и результат

Подготовлен нормализованный `price-list.json` и документ `test-data.md` для проверки алгоритма формирования цены. В документе 28 реалистичных заказов: базовые операции для пяти категорий техники, ремонт проколов, пластыри, вентили, удлинители, грибки и заказ на 8 колёс.

Текущий поток получения параметров и прайса, клиентский предварительный расчёт и серверный контроль суммы зафиксированы в `current-price-calculation.md`.

Алгоритм вынесен в локальный пакет `@autoservice/pricing`. Redux-селектор и серверный `PriceService` теперь являются адаптерами к общей функции `calculateOrderPrice`; отдельные копии расчёта удалены. Сервер по-прежнему самостоятельно получает прайс компании и сохраняет рассчитанную им сумму.

## Изменения API, схемы и данных

Пути endpoint не изменились. В тело создания/редактирования заказа добавляется значение отдельного параметра `tire_repair`: массив составных операций с выбранной опцией каждой группы и количеством. Сервер строит проверку по типу `COMPOSITE_LIST` и метаданным групп, проверяя наличие всех цен.

В `ordersOptionValues` добавлено nullable-поле `compositeOperationId`; существующие заказы не изменены. Идемпотентная миграция добавляет тип `COMPOSITE_LIST`, параметр `tire_repair`, метаданные групп его опций, цены материалов и работ, опции 225–229, а также доступ к опции 224. Перед записью создан и проверен ограниченный дамп справочников; операционные и пользовательские данные в него не вошли.

В карусели формы универсальный компонент составного параметра создаётся по данным API. Карточка «Шиноремонт» следует сразу после «Материалов» благодаря значениям `order` в справочнике; специальных проверок имени параметра и диапазонов ID в UI нет. Выбор внутри групп использует общий `SelectUI` на базе `react-select`, поэтому поддерживает поиск и сохраняет оформление остальных селекторов формы.

## Ограничения

Поле `sourceTotal` в `price-list.json` сохранено только для сверки с исходной таблицей. Ожидаемые цены тестов рассчитываются по уточнённому правилу пользователя: материал плюс один выбранный способ ремонта.

Существующее правило выбора более специфичной строки сохранено, но теперь замена выполняется только для одинаковой основной опции. Это позволяет начислять материал и работу отдельно. Ручной smoke в Chrome не выполнялся: FSB в текущем окружении недоступен; API smoke и production-сборка клиента пройдены.
