# Итог реализации

## Поведение и результат

Подготовлен нормализованный `price-list.json` и документ `test-data.md` для проверки алгоритма формирования цены. В документе 28 реалистичных заказов: базовые операции для пяти категорий техники, ремонт проколов, пластыри, вентили, удлинители, грибки и заказ на 8 колёс.

Текущий поток получения параметров и прайса, клиентский предварительный расчёт и серверный контроль суммы зафиксированы в `current-price-calculation.md`.

Алгоритм вынесен в локальный пакет `@autoservice/pricing`. Redux-селектор и серверный `PriceService` теперь являются адаптерами к общей функции `calculateOrderPrice`; отдельные копии расчёта удалены. Сервер по-прежнему самостоятельно получает прайс компании и сохраняет рассчитанную им сумму.

## Изменения API, схемы и данных

Пути endpoint не изменились. В тело создания/редактирования заказа добавляется значение отдельного параметра `tire_repair`: массив составных операций с выбранной опцией каждой группы и количеством. Сервер строит проверку по типу `COMPOSITE_LIST` и метаданным групп, проверяя наличие всех цен.

В `ordersOptionValues` добавлено nullable-поле `compositeOperationId`; существующие заказы не изменены. Идемпотентная миграция добавляет тип `COMPOSITE_LIST`, параметр `tire_repair`, метаданные групп его опций, цены материалов и работ, опции 225–229, а также доступ к опции 224. Перед записью создан и проверен ограниченный дамп справочников; операционные и пользовательские данные в него не вошли.

В карусели формы универсальный компонент составного параметра создаётся по данным API. Карточка «Шиноремонт» следует сразу после «Материалов» благодаря значениям `order` в справочнике; специальных проверок имени параметра и диапазонов ID в UI нет. Выбор внутри групп использует общий `SelectUI` на базе `react-select`, поэтому поддерживает поиск и сохраняет оформление остальных селекторов формы.

## Реализация составных работ

- Для типа `COMPOSITE_LIST` клиент хранит массив независимых операций. Каждая операция содержит собственный идентификатор, массив выбранных опций групп и количество.
- `CompositeParameterList` формирует группы по метаданным `optionGroup`, выводит их по `optionGroupOrder` и использует переведённые подписи `optionGroupTranslationRu`. Поэтому компонент подходит не только для шиноремонта и не привязан к конкретным ID опций.
- При добавлении и изменении операции клиент оставляет только варианты, для которых существует строка прайса с учётом уже выбранных параметров заказа и предыдущих групп операции. Несовместимый способ работы не предлагается пользователю.
- Каждая добавленная работа отображается отдельной вертикальной карточкой. Поля внутри карточки и несколько карточек располагаются сверху вниз; экспериментальная горизонтальная компоновка и изменение ширины карусели были отменены после проверки интерфейса.
- Значения составного параметра включаются в формат данных создания и редактирования заказа, восстанавливаются из ответа API и очищаются вместе с остальными значениями формы.
- При сохранении сервер преобразует каждую составную операцию в отдельные строки `ordersOptionValues`, связывая выбранные материал и способ через `compositeOperationId`. Это позволяет восстановить границы операций и не смешивать одинаковые опции из разных ремонтов.
- Сервер проверяет структуру всех групп, доступность выбранных опций компании, отсутствие повторов и наличие подходящих цен. Клиентский фильтр служит подсказкой интерфейса, но не заменяет серверную проверку.
- Общий модуль цены считает базовые параметры один раз, затем отдельно каждую составную операцию. Количество операции применяется к материалу и выбранному способу работы, а более специфичная цена заменяет менее специфичную только для той же основной опции.

## Миграция, поставка и откат

При запуске сервера миграции последовательно добавляют значение `COMPOSITE_LIST` в тип параметра, nullable-колонку `compositeOperationId`, параметр `tire_repair`, метаданные групп, недостающие опции компании и строки прайса. Операции миграции идемпотентны: повторный запуск не меняет порядок параметров и не создаёт дубликаты цен или справочников.

Безопасный порядок поставки: применить сервер с миграцией, убедиться в успешном старте и наличии нового параметра в API, затем развернуть клиент. Nullable-колонка сохраняет совместимость с ранее созданными заказами.

Для отката интерфейса и расчёта возвращаются предыдущие версии клиента, сервера и общего пакета. До удаления добавленных справочных данных необходимо убедиться, что нет заказов с `tire_repair` или заполненным `compositeOperationId`; иначе сначала требуется сохранить или преобразовать эти операции. Ограниченный дамп справочников позволяет восстановить исходное состояние затронутых справочных таблиц без перезаписи пользователей, смен, сессий и заказов.

## Ограничения

Поле `sourceTotal` в `price-list.json` сохранено только для сверки с исходной таблицей. Ожидаемые цены тестов рассчитываются по уточнённому правилу пользователя: материал плюс один выбранный способ ремонта.

Существующее правило выбора более специфичной строки сохранено, но теперь замена выполняется только для одинаковой основной опции. Это позволяет начислять материал и работу отдельно. Ручной smoke в Chrome не выполнялся: FSB в текущем окружении недоступен; API smoke и production-сборка клиента пройдены.
