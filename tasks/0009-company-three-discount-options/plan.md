# Изменить список скидок компании 3

Цель: для компании 3 настроить возможные скидки 10%, 15%, 20%. Остальные компании не затрагивать. До реализации уточнить, нужен ли отдельный вариант «0%».

Текущий read-only аудит локальной БД: компании 3 доступны 0% (опция 30) и 10% (31); опция 30 также используется компанией 1. 15% и 20% в текущем справочнике не обнаружены. Расчёт в `packages/pricing/src/calculate-order-price.ts` определяет процент по подписи выбранной опции; без выбранной скидки коэффициент равен 1, при этом скидка применяется только к ценам с признаком `discountImpact`. Нельзя изменять общие опции так, чтобы затронуть другую компанию или историю.

До реализации изучить использование скидок в форме и заказах, определить способ добавления/повторного использования опций, проверить связанные данные и историю, подготовить идемпотентную миграцию и откат. Проверить без скидки и все разрешённые проценты, округление и позиции без скидки, другие компании, создание и редактирование заказов, сборки и тесты. Пользователь указал, что для каждой операции с локальной БД не требуется создавать резервную копию и отдельную тестовую базу; запись данных выполняется после согласования конкретного плана.

## Согласованное решение

Пользователь подтвердил список 0%, 10%, 15%, 20%; 0% остаётся для возврата к полной цене. В справочном снимке добавить опции 15% и 20% и включить их только компании 3. Для существующих БД — транзакционная идемпотентная миграция: найти существующие опции параметра скидки по точной подписи или создать недостающие с автоматическим ID; обновить только `optionsList` компании 3, сохранив другие параметры и опции и исключив иные скидки из выбора. Общие опции, другие компании, цены и старые заказы не изменять. При неоднозначных дубликатах подписей остановиться. Записать отметку миграции в той же транзакции. Схема и API не меняются. Миграцию запускать после существующих миграций, соблюдая актуальность sequence.

Откат: вернуть прежний список скидок в настройке компании 3, предварительно проверив возможные новые заказы; не удалять справочные опции, на которые могут ссылаться заказы. Новый код безопасно собрать до включения миграции в запуск; после применения проверить её повторяемость, состав скидок и изоляцию других компаний. Тестировать коэффициенты 0, 10, 15, 20% в калькуляторе, выбранные позиции без скидки и формы; затем backend/client build и релевантные тесты. Пользователь согласовал конкретное изменение локальных данных, без обязательной новой резервной копии и отдельной тестовой БД. Рабочий сервер не менять без отдельного указания.
