# Итог реализации

Для компании 3 доступны скидки 0%, 10%, 15% и 20%. Вариант 0% оставлен для отмены ранее выбранной скидки. Существующая логика применяет скидку только к ценам с `discountImpact`, а без выбранной скидки оставляет полную стоимость.

Идемпотентная транзакционная миграция `company_three_discount_options_0_10_15_20` находит подходящие опции по точной подписи или создаёт 15% и 20% с автоматическими ID, затем обновляет только список опций компании 3. Дубликаты подписей приводят к остановке; другие компании, существующие опции, цены, схема, API и заказы не меняются. Начальные справочные данные дополнены для новой БД. В локальной БД миграция применена дважды: второй запуск ничего не меняет. Компания 1 сохранила свои 0%, 10%, 50%, 100%.

Откат: вернуть прежние ID скидок компании 3 в `companiesParametersOptions.optionsList` с учётом изменений, сделанных после миграции. Новые опции нельзя удалять без проверки ссылок в заказах. Для повторного применения после отката потребуется согласованно обработать запись миграции. До поставки в другое окружение проверить данные и актуальную sequence; рабочий сервер не обновлялся.

Проверены 37 тестов общего калькулятора, в том числе 0%, 10%, 15%, 20% и цена без скидки, backend build и 213 тестов, frontend build и 44 теста. В браузере подтверждены четыре варианта и расчёт 15%, 20%, возврат к 0% на сумме 1450 ₽. Полное сохранение и редактирование тестового заказа вручную не выполнялось. Дополнительную резервную копию и отдельную локальную БД для этой миграции не создавали согласно указанию пользователя.
