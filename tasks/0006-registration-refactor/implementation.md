# Результат рефакторинга регистрации

Дата:2026-11-02. Ветка:0006-registration-refactor. Production/Analysis не обновлялись.

## Поведение

Из AuthService.register удалены console.log(userDto) и логирование сырой ошибки. Клиенту сохраняется прежний безопасный текст ошибки создания пользователя. DTO, парольные требования и формат успешного ответа id/name/roles/token не изменены.

Пользователь уже создавался с companyId новой компании и ролью ADMIN. Эта реализация сохранена, regression test подтверждает передачу ID созданной компании, создание сессии и прежний ответ. Дополнительный независимый механизм членства не вводился.

На POST /auth/register добавлен singleton RegistrationRateLimitGuard: один запрос с IP за10000ms. Считаются в том числе неверные DTO и неуспешные попытки, потому что guard выполняется до ValidationPipe и сервиса. Повторные запросы возвращают429, Retry-After в секундах и message «Существует лимит на частоту регистрации. Попробуйте позже». Отказы не продлевают интервал, ровно через10сек запрос разрешён. /auth/login этим guard не ограничивается.

Для IP используется Express req.ip, fallback socket.remoteAddress. В main явно задан trust proxy: один hop только при TRUST_PROXY=1, иначе false. Production Compose задаёт1, backend по-прежнему не имеет host port; Nginx перезаписывает X-Forwarded-For значением remote_addr, не доверяя переданному клиентом заголовку. Локальная разработка не доверяет forwarded-заголовкам. Инструкция deploy/README.md дополнена.

Клиентский registerUser → HandlerAxiosError → rejected reducer → RegistrationForm уже отображает response.data.message. Новый формат429 совместим без изменения frontend.

## Ограничения

Счётчик in-memory для текущего одного backend-процесса, при перезапуске сбрасывается. Истёкшие IP очищаются при следующем запросе, проход очистки не чаще одного раза за10секунд. Для нескольких процессов/реплик требуется общий store. CDN/дополнительный proxy потребует пересмотра доверенной цепочки; произвольное включение trust proxy для открытого backend небезопасно.

Атомарная транзакция создания компании/пользователя/роли/сессии не добавлялась: прежний порядок и companyId сохранены. Полная успешная регистрация проверена mock-тестом, не созданием реальных компаний в существующей БД. Существующие файлы логов не очищались; удалён логирующий код пути регистрации.

Незакоммиченная документация задачи0005 сохранена отдельно, в эту задачу не включается. Новые runtime dependencies не добавлялись.
