## SR5-1 — P2: подтверждение администратора блокирует работников

Место: `server/src/auth/roles.guard.ts:70–75`.

RolesGuard проверяет requiredRoles.includes(ADMIN), а затем отклоняет любого пользователя с confirmed=false. Это список ролей, разрешённых методу, а не роли текущего пользователя. Поэтому работник только с WORKER и валидной сессией не может пользоваться endpoint с @Roles(ADMIN, WORKER), включая операции смен и заказов. По правилам проекта дополнительное подтверждение требуется администраторам. Например, неподтверждённый WORKER должен проходить проверку роли для создания заказа, но получает 403 до проверки своих ролей.

Подтверждение: настоящий RolesGuard с синтетическими UsersService, UsersSessionsService и Reflector; пользователь имеет только WORKER, endpoint допускает ADMIN и WORKER. При confirmed=false canActivate возвращает false, при confirmed=true — true, остальные входные данные одинаковы. Воспроизведение выполнено вне репозитория, без запросов или записей в рабочую БД. Наличие затронутых работников в текущей БД не проверялось.

Рекомендация: определять необходимость подтверждения по фактической административной роли пользователя, сохранив действие ScipConfirmed. Добавить проверки неподтверждённого WORKER на смешанном endpoint, неподтверждённого ADMIN, смешанных ролей и явного пропуска подтверждения.
