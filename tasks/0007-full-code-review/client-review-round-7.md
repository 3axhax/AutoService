## R7-1 — P2: правки, введённые во время сохранения, исчезают после успешного ответа

Место: `client/src/features/editAdditionalWorkForm/ui/EditAdditionalWorkForm.tsx:99–112`; аналогично `client/src/features/editOrderForm/ui/SwitchParameterType.tsx` и CompositeParameterList.

pending блокирует отправку формы, но не поля и операции над её черновиком. Thunk уже захватил значения до отправки POST. Пользователь может изменить описание, сумму или опции, пока запрос выполняется. После успешного создания reducer помечает текущий черновик active=false независимо от того, изменился ли он после отправки. ActiveList скрывает форму. При редактировании формы закрываются через onSuccess. Более новые правки не отправлены и не предлагаются к сохранению; в списке виден старый снимок.

Воспроизведение в браузере с настоящими WorkerShift, EditAdditionalWorkForm, Redux и отложенным Axios: заполнить BEFORE SAVE/100 → нажать Записать → до ответа заменить поля на AFTER SAVE/200 → завершить запрос. Поля принимают ввод, затем форма исчезает; в списке BEFORE SAVE/100. Результат POST в стенде возвращает ровно первоначально отправленные значения, без симуляции обработки БД. Аналогичный риск в заказах подтверждается той же схемой thunk → изменяемый буфер → active=false/onSuccess; отдельно браузером заказ не проверялся.

Направление исправления: блокировать поля, составные операции и удаление отправляемого черновика на время записи либо учитывать версию отправленного снимка и сохранять более новые изменения для следующей записи. Не удалять/скрывать текущие изменения только по успешному ответу на более раннюю версию.

## R7-2 — P2: ошибки закрытия смены и удаления записей не видны пользователю

Место: `client/src/features/shift/actionBlock/CloseShift.tsx:18–21`, `client/src/widgets/workerShift/ui/ClosedAdditionalWorksList/AdditionalWorksListActionButton.tsx`, `client/src/features/ordersListActionButton/OrdersListActionButton.tsx`; общее преждевременное закрытие подтверждения — `client/src/shared/ui/Modal.tsx:86–90`.

Modal закрывается перед запуском onAccess. Обработчики вызывают thunk без обработки rejected. Ошибка закрытия/создания смены остаётся в shifts.error, который не отображает ни один компонент. Ошибки удаления остаются в order.error/additionalWorks.error, читаемых только редакторами; при обычном удалении редактора нет. ListReadStatus читает только readError, поэтому не сообщает о сбое записи. После отказа API или сети подтверждение исчезает, запись/смена остаётся на месте, объяснения и явного результата нет.

Браузером на настоящих компонентах и синтетическом API подтверждены два пути: Закончить смену → Подтвердить → отклонённый запрос: окно закрыто, активная смена осталась без ошибки на экране; Удалить дополнительную работу → Подтвердить → отклонённый запрос: строка осталась, окно закрыто, ошибки нет. Аналогичный путь удаления заказа подтверждён кодом. API БД не вызывался.

Направление исправления: показывать результат неуспешной операции на видимом экране либо оставлять подтверждение с ошибкой и возможностью явного повтора. Отдельно обозначать ошибку записи и сбой последующего чтения. Повтор записи должен запускаться пользователем, а не автоматически.
