# Обновление паролей dev-пользователей

Дата: 2026-11-02.

По прямому запросу пользователя заменить пароли двух аккаунтов из игнорируемого `testData/dev.json` в локальной БД AutoService. Read-only аудит подтвердил по одному совпадению email для каждого login. Удалённый сервер не затрагивается.

Источник формата: `testData/dev.json`; хранение — `server/src/users/users.model.ts`, проверка и bcrypt cost 10 — `server/src/auth/auth.service.ts`.

План: сохранить защищённую игнорируемую копию исходного файла и прежних хешей; сгенерировать уникальные случайные пароли; обновить только `users.password` по проверенным id/email в транзакции и файл атомарной заменой; проверить bcrypt.compare для каждого аккаунта и неизменность остальных полей файла. Не запускать NestJS и startup migrations.

Схема, API, роли, заказы и сессии не меняются. Существующие сессии остаются действительными. Риск — рассогласование файла и БД: при ошибке до commit выполнить rollback и восстановить файл. Для последующего отката использовать защищённую локальную копию по отдельному запросу. Секреты и хеши в документацию и Git не включать.

Критерии: ровно два изменённых пользователя, новые пароли уникальны, оба хеша проходят bcrypt.compare, JSON читается, файл и резервная копия имеют права 0600 и исключены из Git; git diff --check.

Уточнение 2026-11-02: после первой ротации пользователь ограничил длину восемью символами. Выполнить повторную ротацию: разные пароли ровно по 8 символов, латинские буквы обоих регистров и цифры без неоднозначных символов, криптографический генератор. Остальной план сохраняется.
