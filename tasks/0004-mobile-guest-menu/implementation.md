# Результат

Дата: 2026-11-02. Ветка: 0004-mobile-guest-menu.

Для гостя добавлена возможность свернуть и открыть мобильное меню через существующий NavigationUI. Navigation передаёт canCollapsedOnMobile для неавторизованного пользователя; мобильный transform и кнопки учитывают этот флаг, desktop max-height по-прежнему зависит только от прежнего canCollapsed. Кнопки гостя скрываются на desktop через lg:hidden. Worker сохраняет прежний canCollapsed; список пунктов, роли и условия авторизации не менялись. Toggle получил aria-label и aria-expanded, крестик — доступную подпись.

Используются прежние hideNavigation/Redux и appSettings в localStorage. При сохранённом открытом состоянии меню можно закрыть, при скрытом — повторно открыть. Отдельного меню и нового механизма хранения состояния нет.

Проверки в реальном встроенном браузере на локальном dev-контейнере:
- До изменения viewport 390×844: guest меню перекрывало MainPage, кнопок закрытия не было.
- После изменения: крестик закрывает, кнопка Показать меню открывает, Скрыть меню закрывает.
- После reload сохранено скрытое состояние; DOM elementFromPoint в центре MainPage подтверждает, что заголовок не перекрыт header.
- Вход/Регистрация открывает модальное окно входа; закрывается Escape, форма не отправлялась.
- Desktop 1280×900 после завершения анимации: header на x=0, без translate, вход виден, обе кнопки сворачивания display:none, горизонтального переполнения нет. Временный viewport override сброшен.
- docker exec clientAutoService npm run build: TypeScript/Vite успешны, прежние предупреждения CSS/bundle сохраняются.

Backend/БД/API и production не менялись, приложение на сервере не обновлялось. Отдельный вход worker/admin не выполнялся; сохранение их прежних условий подтверждено diff, frontend build проверяет совместимость props. Автоматический UI test harness не добавлен: регрессия воспроизведена и проверена через реальный браузер.

Откат: вернуть два frontend-файла Navigation.tsx и NavigationUI.tsx. Миграций схемы/данных нет, существующие appSettings совместимы. Задача готова к пользовательской приёмке; commit/push после приёмки по правилам проекта.

## Автоматическое сворачивание при выборе

2026-11-02 по уточнению пользователя добавлен общий handleItemSelect: обычные ссылки, action-кнопки и пункты dropdown закрывают мобильное меню и вложенный список. Action вызывается после установки hideNavigation=true в том же событии: Вход/Регистрация открывает модалку уже со скрытым меню. Открытие самого dropdown не сворачивает навигацию; click выбранного подпункта останавливает всплытие, чтобы родитель не открыл список снова. На desktop автоматическое сворачивание не выполняется; matchMedia проверяется на момент клика с границей 1024px.

Проверка во встроенном браузере: на 390px выбор Вход/Регистрация оставляет модалку открытой и aria-expanded=false у меню после завершения анимации. На 1280px тот же выбор открывает модалку, но сохраняет aria-expanded=true; гостевой desktop header не сворачивается. Поля/пароли не изменялись, формы не отправлялись. Screenshot результата сохранён вне Git с обрезкой до полей, без личных данных. После проверки модалка закрыта, меню скрыто, viewport override сброшен.

Повторный client build успешен. Пункты обычных ссылок/dropdown проверены по обработчикам и сборке; гостевой сценарий открытия модального входа — в браузере. Production и БД не изменялись.
